# AGENTS.md

This file contains guidelines and commands for agentic coding agents working in this Symfony 8.0 codebase.

## Build/Test Commands

### Core Commands
- `php bin/console cache:clear` - Clear Symfony cache
- `php bin/console assets:install %PUBLIC_DIR%` - Install assets to public directory  
- `php bin/console importmap:install` - Install JavaScript dependencies via importmap
- `php bin/console asset-map:compile` - Compile mapped assets

### Testing
- `./vendor/bin/phpunit` - Run all PHPUnit tests
- `./vendor/bin/phpunit --filter <TestName>` - Run specific test
- `./vendor/bin/phpunit tests/<TestFile>.php` - Run specific test file
- `php bin/console make:test` - Create new test class

### Quality Assurance
- `./vendor/bin/phpstan analyse src` - Run PHPStan static analysis (level 1)
- `php bin/console lint:yaml config/` - Lint YAML files
- `php bin/console lint:twig templates/` - Lint Twig templates
- `php bin/console lint:translations` - Lint translation files
- `php bin/console lint:container` - Check service container configuration

### Database
- `php bin/console doctrine:migrations:migrate` - Run database migrations
- `php bin/console doctrine:migrations:sync-metadata-storage` - Sync migration metadata
- `php bin/console doctrine:database:create` - Create database if needed

### Translations
- `php bin/console survos:translate` - Test translation engines
- `php bin/console babel:stats` - Show translation statistics

### Import/Export
- `php bin/console importmap:update` - Update JavaScript packages
- `php bin/console importmap:outdated` - Check for outdated JS packages

## Code Style Guidelines

### PHP Code Style
- Use `declare(strict_types=1);` at the top of all PHP files
- Classes should be `final` unless explicitly designed for inheritance
- Use `readonly` properties where appropriate for immutable value objects
- Use property promotion in constructors when appropriate
- Follow PSR-12 coding standards
- Use type hints for all method parameters and return types
- Use nullable types (`?string`) for optional fields

### Naming Conventions
- Classes: PascalCase (e.g., `AmstRepository`)
- Methods: camelCase (e.g., `findByCode`)
- Properties: camelCase with public properties for entities (Doctrine convention)
- Constants: UPPER_SNAKE_CASE (e.g., `FILTERABLE_FIELDS`)
- Files: PascalCase matching class name for PHP files

### Entity Conventions
- Use attribute-based Doctrine mapping (`#[Entity]`, `#[Column]`, etc.)
- Public properties for entity fields (as seen in Amst entity)
- Use `#[Id]` for primary key fields
- Use `#[Column(type: Types::STRING, length: 255, nullable: true)]` pattern
- Add comprehensive PHPDoc blocks with field statistics
- Use generated code markers where appropriate: `@generated by code:entity from profile`

### Controller Conventions
- Controllers can extend `AbstractController` or use decoupled approach with `ControllerHelper`
- Use attribute-based routing: `#[Route(path: '/home', name: 'app_homepage')]`
- Use `#[Template('template/path.html.twig')]` for template rendering
- Return arrays for template data or `Response` objects
- Use constructor injection with `#[AutowireMethodOf]` for decoupled controllers

### Repository Conventions
- Extend `ServiceEntityRepository`
- Use `final` class modifier
- Constructor with `ManagerRegistry` injection
- Auto-generated repositories are sufficient for basic CRUD

### JavaScript/Frontend
- Use Importmap for dependency management
- Main entrypoint: `assets/app.js`
- Styles in `assets/styles/app.css`
- Use Stimulus.js for JavaScript behavior
- Import CSS alongside JS modules
- Bootstrap and Tabler CSS frameworks available

### Translation Patterns
- Use Survos Babel bundle for translatable entities
- Backing properties pattern: `fieldNameBacking` with public translatable `fieldName`
- Use `#[Translatable(context: NULL)]` attribute
- Translation files in `translations/` directory (YAML format)

### API Platform
- Entities marked with `#[ApiResource]` attributes
- Use `#[Get()]` and `#[GetCollection()]` operations
- Configure searchable/filterable fields in constants
- Use MeiliSearch integration for search functionality

### Error Handling
- Use strict types and null checks
- Prefer early returns and guard clauses
- Use Symfony's built-in exception handling
- Log errors appropriately for debugging

### File Organization
- `src/Entity/` - Doctrine entities
- `src/Repository/` - Doctrine repositories  
- `src/Controller/` - Controllers (including Admin/)
- `src/Service/` - Business logic services
- `src/Workflow/` - Workflow definitions
- `templates/` - Twig templates
- `assets/` - Frontend assets
- `config/packages/` - Bundle configuration
- `translations/` - Translation files

### Security
- Never commit secrets or credentials
- Use environment variables for sensitive configuration
- Follow Symfony security best practices
- Validate all user input appropriately

### Git Workflow
- Create meaningful commit messages following the project's existing pattern
- Run tests and quality checks before committing
- Ensure `php bin/console cache:clear` works after changes
- Test database migrations when modifying entities
